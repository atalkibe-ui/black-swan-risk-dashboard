# Внутренний сервер дашборда

Сервис отдает дашборд и предоставляет same-origin API для аналитического
комментария. Ключ модели и промпт никогда не передаются браузеру.

## Настройка

Требуется Node.js 20 или новее.

1. Согласованный промпт уже находится в `server/prompts/analysis-prompt.txt`.
2. Задайте серверные переменные окружения:

```text
OPENAI_API_KEY=<секретный ключ>
OPENAI_MODEL=<разрешенная модель>
OPENAI_BASE_URL=https://api.openai.com/v1
AI_API_MODE=responses
AI_ENABLE_WEB_SEARCH=true
HOST=127.0.0.1
PORT=8080
```

Для внутреннего OpenAI-совместимого шлюза замените `OPENAI_BASE_URL`. Если шлюз
использует Chat Completions API, задайте `AI_API_MODE=chat-completions`. При
включенном поиске Responses API получает инструмент `web_search`, а Chat
Completions API — параметр `web_search_options`. Шлюз и выбранная модель должны
поддерживать соответствующий режим. Токен можно не задавать, если аутентификацию
выполняет сетевой шлюз организации.

Дополнительные переменные:

```text
AI_PROMPT_FILE=/secure/path/analysis-prompt.txt
AI_CACHE_FILE=/var/lib/black-swan/latest-analysis.json
AI_TIMEOUT_MS=60000
MAX_REQUEST_BYTES=65536
AI_ENABLE_WEB_SEARCH=true
```

## Запуск

```bash
cd server
npm start
```

После запуска страница доступна по `http://127.0.0.1:8080/`, проверка состояния
по `GET /health`. В продуктивной среде сервис следует публиковать через
внутренний HTTPS reverse proxy с корпоративной аутентификацией. Для нескольких
экземпляров сервиса `AI_CACHE_FILE` должен указывать на общее постоянное хранилище
либо кэширование следует заменить внутренней БД.

## API

- `GET /api/ai-analysis` возвращает последний сохраненный ответ или HTTP 204.
- `POST /api/ai-analysis` принимает текущий срез индексов, добавляет его к
  серверному промпту, запрашивает модель и сохраняет результат.

Промпт, токен и адрес поставщика не выдаются клиенту. Входной JSON ограничен по
размеру и проверяется перед отправкой модели.
